# 主题1：Agentic Coding（含Vibe Coding对比）

## Compiled Truth

Agentic Coding 与 Vibe Coding 代表了AI辅助编程的两个不同演进阶段。Vibe Coding是AI辅助编程的初级阶段，由Karpathy于2025年2月提出，其核心特征是用户"完全不看代码，纯靠感觉提需求"，本质上是超级自动补全，用户扮演"甲方"角色。而Agentic Coding是AI自主编程的生产级形态，自2026年2月开始转向，其核心是AI Agent能够自主规划、执行、调试、自修，用户角色从"提需求的人"转变为"验收结果的人"，扮演"技术负责人"的角色。

这一范式迁移的关键在于，Vibe Coding适合快速原型或Demo开发，但容易导致代码质量下降（"屎山"）；而Agentic Coding虽然初期门槛更高，但适合生产级工程，可维护性和工程化程度更强。用户无需懂代码细节，但必须能判断功能是否"好用"，并在提需求时包含明确的验收标准。

## 关键要点

- **核心区别**：Vibe Coding是超级自动补全（甲方模式），Agentic Coding是自主编程Agent（技术负责人模式）
- **需求明确**：提需求时必须包含明确的验收标准，而非模糊描述
- **流程优化**：让Agent先出Plan再执行，并实施逐轮验收
- **价值判断**：用户不懂代码不等于不能判断功能是否"好用"
- **场景匹配**：Vibe适合原型但易导致"屎山"；Agentic适合生产级工程，可维护性强

## Plan 模式深度剖析：阿基米德式提问法

*2026.6.18 补充——基于 Agentic Coding 工具演化观察*

### 演化路径：Plan 模式从 Claude Code 到行业标配

Plan 模式的核心思路是「先想清楚再动手」——在真正执行之前把计划、涉及的文件、可能的坑都列出来，让用户 review 之后再执行。

**关键节点：**

| 工具 | Plan 模式特点 |
|------|-------------|
| **Claude Code**（最早） | 把 Plan 做成一等公民，`/plan` 命令让 Agent 先出结构化 Markdown 计划再执行 |
| **Codex CLI** | OpenAI 跟进 Plan/Workflow 模式，偏「先探索代码库再出方案」 |
| **OpenCode** | 更轻量，但同样支持 plan-before-code |
| **Cursor Agent** | 在 IDE 里做 Plan，更贴近开发者的即时反馈循环 |
| **GitHub Copilot Agent Mode** | 微软跟进，把 Plan 嵌入 PR 工作流 |

这不仅是功能层面的跟进，更是一种**交互范式的转变**：从「AI 是副驾驶帮你补代码」，变成「AI 是 contractor，你先 approve 方案它再施工」。

### 哲学本质：Plan 模式 = 阿基米德式提问法

Plan 模式和苏格拉底/阿基米德式提问法的底层逻辑完全一致：

- 核心都是**先对齐需求，再执行**
- 双方（人和 AI）在动手前确认理解度达到足够高的水平
- 把「人的判断」插在「AI 的执行」前面，避免方向性错误

> Plan 模式不是在拖慢速度——它是在用 5% 的沟通时间，避免 100% 的方向性返工。

### 实践约束：95% 理解度门禁

当需求不够清晰时，Agent 应该**主动提问澄清**，而非假设理解后直接执行。确认理解度达到 95% 以上后再动手。

这是 Plan 模式精神在单次对话中的落地——不只是大任务需要 Plan，每一次「我不确定你什么意思」的场景，都应该触发一次 mini-Plan（即提问确认）。本质上和 Claude Code 的 `/plan` 命令是同一个道理：**先对齐，再施工**。
