# 主题3：Harness工程

## Compiled Truth

Harness工程代表了AI工程范式的根本性迁移：工程师的角色从"写代码的人"转变为"设计缰绳和鞍具的人"。其本质是设计一个"笼子"或环境，让AI能够在其中自主奔跑、自我纠错、持续交付。

OpenAI 的实践：一个3人扩展至7人的团队，在5个月内产出约100万行代码，而人工编写代码为0行，效率提升约10倍。

## 关键要点

- **范式迁移**：从"编码者"变为"环境设计者"
- **核心三原则**：设计环境（Design Environment）、明确意图（Clear Intent）、构建反馈回路（Feedback Loop）
- **关键跃迁**：从"盲写"到"生成-验证-迭代"的闭环工作流

## 📌 每日对话（2026-07-30）

**碰撞：** 用户昨日亲手搭建了 Harness 四层中的三层（校验层 skill_validator.py、增量突变 skill_mutate.py、依赖图 skill_graph.py），用于规范 Agent 对 Skill 的操作。但碰撞点在于：Harness 的受益者应是 Agent 的使用者（用户本人），而非 Agent 的建造者（Agent 自己）——这三层的设计优化了 Agent 的工程质量，但尚未降低用户使用 Agent 结果出错的概率。

**纵深：** 早期赛车（无安全带+无头盔，纯手艺比拼）→ 现代 F1（六点式安全带+HANS装置+防滚架）。Harness 不是限制车手自由，是设计一个环境让车手敢把油门踩到底——知道笼子扛得住。

**落地：** 校验层目前拦截的是「Agent 写坏的 SKILL.md 格式」。但用户更需要的可能是「Agent 建议改的 Skill 是否真的符合我的需求」——这是本质不同的两件事。校验层应该从语法校验进化到语义校验（Context validation），类似 Code Review 从 lint 升级到架构评审。

## 📌 每日对话（2026-08-04）

**碰撞：** 用户昨日在搭会议纪要+素材拉取的流水线——协作群8个bot是环境，「拿跟客户匹配的材料」是意图，前两条 Harness 原则都到位。但反馈回路缺失：当样板间给三条材料、用户挑一条发给客户后，挑对挑错的信息不回到流水线里——下次同一个客户的筛选不会更精准，每次会议结束流水线从零开始。

**纵深：** 人体免疫系统——先天性免疫（皮肤、巨噬细胞）是 Harness 第一层，设计好环境防所有入侵。但真正让免疫系统厉害的，是适应性免疫的反馈回路：第一次遇到新病毒（错选的材料），下次再见同类病毒（类似客户场景），抗体筛选从几天缩到几小时。没有记忆层的 Harness 只能防，不能学。

**落地：**每做完一次客户回访、发出一张带材料的会议纪要——材料有没有被客户转发或认可？这个信号回到流水线里了吗？还是只活在那一次会议里，下次同行业的客户又从头来？

## 📌 每日对话（2026-08-20）

**碰撞：**昨天 TraeWork 直播 Damon 的工作流「每步都有人工拍板点」（口播三关、人工审片），用户觉得和人机协作范式同频。但用户 8/04 刚说过自己的会议流水线「反馈回路缺失」——人工拍板点 ≠ 反馈回路：拍板结果有没有回到系统里让下次筛选更准？Damon 的检查记录是给人看的，不是喂回给系统的。如果 Harness 第三原则是「构建反馈回路」，那「每步停下来人工看」到底是闭环建好了，还是闭环没建、靠人肉兜底？

**纵深：**任天堂《旷野之息》式开放世界关卡设计——设计师不教玩家怎么玩，只设计物理规则、地形线索、奖励节奏，玩家自己探索试错，系统即时反馈（血量/天气/装备）。玩家在环境里读出目标，而不是被弹窗告知：这就是「设计环境、明确意图、构建反馈回路」的交互式教科书。与 8/04 免疫系统类比不同：免疫是系统自己学，关卡设计是环境在教。

**落地：**卡兹克文章最值钱一句「流程不顺没人帮你开发，只能自己和 Agent 解决」——一线自己搭自己的 Harness。米敏 FAB Skill 五步法（说清场景→AI 复述→给参考→小批量试）是「教它工作→搭工具」的现成 demo。客户说想建 AI 中台时反着卖：先让一个一线员工用五步法搭出自己第一个 Skill，他要的是「从只能忍受流程，到知道流程可以被自己改掉」的主动权——那是中台给不了的。

## 📌 每日对话（2026-09-21）

**碰撞：** 用户 9/20 亲问「Anthropic 开放 Agent.MD 有什么意义」，当时答：行业统一了「给 agent 看的说明书」（README 给人看，AGENTS.md 给 agent 看），价值在项目规范不绑死某一家 AI 供应商。但拿 Harness 三原则量：环境（项目结构）与意图（要干什么）已随 AGENTS.md 标准化，第三条「反馈回路」缺席——AGENTS.md 被所有 agent 读懂只说明说明书更好用，agent 照它干活对不对没有任何信号回流。行业只能用土办法验收：同日旁听的豆包工作伙伴（Tag）培训，会上给的成败标准是「两周内拿到铁饭碗」，靠「有人还在用它」这种最原始信号。问题：这次开放是补上第三条腿，还是把前两条做到极致、顺手让「没人验证」也标准化了？

**纵深：** 11 世纪圭多·达雷佐把乐谱固定成四线谱——「想弹什么」第一次能跨人、跨代、跨乐器精确传递，即 AGENTS.md 把意图写成人人可读的统一格式的那一步。但记谱法没让音乐变好，只是让「不好」也能被精确复制一千份；音乐真正的跃进来自演奏者把弹奏中发现的东西回写进谱子（复调、和声都是回流出来的）。谱子标准化解决「被读懂」，回流才解决「被改对」，与 8/20「人工拍板点 ≠ 反馈回路」是同一条线的延伸。（避重复：不复用本概念已用的赛车安全带/F1、人体免疫系统、旷野之息关卡设计；亦避开全局「独立评审」结构——米其林出菜口／安然 SOX／药品双盲。）

**落地：** ① 9/22 日程「初筛客户提报 Tag 共创报名表」：会上那条验收标准（两周铁饭碗）本质是一根探针，对客话术可抬一格——不是「给你装个 AI 同事」，而是「帮你装一条能看出它有没有在被用的回路」；报名表里「想用 Tag 落地的场景」写得透不透，决定这条回路有没有地方可接。② 照自己：三层 skill 防护（校验／突变／依赖图）是同一个缺口——环境与意图都有，改完的 skill 有没有真被用上，这一格信号没人采。
