# 主题11：模型选择策略

## Compiled Truth

第一性原理：**场景匹配**，而非"最贵=最好"。存在能力错配问题：顶级模型处理简单任务可能效率更低。

智能路由逻辑：
- 简单任务 → Flash或轻量模型
- 中等任务 → 标准模型（如GPT-4级别）
- 复杂任务 → Pro/最强模型
- 检查校验 → 优先规则引擎

## 关键要点

- **场景优先**：选择模型的唯一标准是任务场景需求，而非模型价格或名气
- **警惕错配**：避免用"牛刀杀鸡"，顶级模型处理简单任务可能效率更低
- **分级路由**：简单→轻量模型、中等→标准模型、复杂→顶级模型
- **成本效益**：通过智能路由在效果和成本间取得最佳平衡
- **规则补充**：对校验、检查类任务，优先考虑规则引擎

## 📌 每日对话（2026-08-02）

**碰撞：** 路由策略「简单→Flash，复杂→Pro」少了一个变量——稳定性。Flash 高峰期 Broken pipe 和 603s 空闲超时把 cron 拖垮，被迫切回 Pro。模型选择的场景匹配公式需要加「可靠性系数」：不只是看"能处理"，还要看"在高峰期能不能稳定地处理"。

**纵深：** 福特 T 型车（一车通吃）→ GM Sloan 五品牌阶梯（雪佛兰/庞蒂亚克/奥兹莫比尔/别克/凯迪拉克）——市场细分逼出来的分层。Sloan 花了 20 年才学会：最低价品牌可靠性不够，顾客不怪那个品牌，怪整个 GM。今天的 Flash/Standard/Pro 路由本质是 Sloan 逻辑的 AI 版。

**落地：** 推给客户也是同样逻辑——不是塞最贵的 Pro 就完事。CRM 自动填单 Flash 足够，但 Flash 在客户业务高峰期崩了，客户不会说「Flash 不行」，客户会说「飞书 AI 不行」。省 Token 的钱，花的却是信任的钱。

## 📌 每日对话（2026-08-08）

**碰撞：** 模型路由公式缺了第四个变量——分类成本。4 月总结的路由逻辑假定「判断任务复杂度」是免费的，但昨天跟 Agent 争论 skill 路由才意识到：分类本身就要付 5554 tokens。Flash/Standard/Pro 不管选哪个，prompt 都得先跑完才能判断复杂度——这个 token 开销该不该加进公式？模型路由公式 = 场景匹配 × 成本效益 × 可靠性 × 分类成本。

**纵深：** 1956 年 Malcom McLean 发明集装箱——把每件货单独分类的成本从总货运的 60%+ 打到标准化。但集装箱没有消灭分类成本，今天每个集装箱过海关还要 ~$200 文书费，只是从「人工分类」变成了「系统分类」。5554-token 注入就是 AI 路由的「海关文书费」——可以优化（拆 profile），不能消灭。Sloan 的阶梯化解决的是「给正确的人正确的车」，集装箱解决的才是「分类本身有多贵」。

**落地：** 推 AI 给客户时标准答案是「看场景选模型」，但没说的半句——「看场景」本身也要成本——才是客户撞的墙。智能伙伴第一步不是 AI 干活，是喂上下文、定规则、分场景（分类成本）。你说服客户别跳过这一步，跟说服自己别跳过 5554 token 注入——同一个道理。下次加一句：路由不是免费的，但值得付。

🏥 **类比迭代（08.08 用户反馈）：** 集装箱→海关类比拐了两道弯，不够直观。改用**急诊分诊台**——进急诊室不管去哪个科，先过护士台量体温问症状（3-5 分钟），这是必经的分类成本。5554 token 注入就是这个分诊台：不直接干活，但决定了活该谁干。分诊可加速，不可取消。客户装智能伙伴第一步——喂上下文、定规则、分场景——同个道理。

## 📌 每日对话（2026-08-21）

**碰撞：** 8/16 用户为省钱把认知对话 cron 从 pro 切回 flash（当时明确提醒过「深度推理任务用 flash 后质量可能略降」），8/21 早 9:05 cron 即 600s 超时失败、卡片未发出——8/02 已记录「可靠性系数」变量，这是同一个坑**第三次**踩。模型路由公式的「可靠性系数」不是理论变量，是用户自己的 cron 在反复交学费。「省 token 的钱，花信任的钱」（8/02 用户原话）再次应验：用户 9:46 问「出什么问题了」的那一下，就是信任的利息。

**纵深：** 西南航空低成本模式——成立的前提是把业务设计成与低成本匹配（短途、点对点、单一机型），从不接跨洋航线。flash 是短途机型，认知对话是跨洋航班：硬飞，省下的油钱全吐在延误上。与 Sloan 阶梯（分层）、集装箱/分诊台（分类成本）结构均不同。

**落地：** ① 认知对话 cron 单独切回 pro，或配 fallback 链（hermes fallback add），别裸奔省钱；② 客户问「AI 哪个便宜」→ 先分任务类型、再谈成本，与今早经历的模型错配完全同构——客户的「Flash 崩溃 = 飞书 AI 不行」风险同样成立。

## 📌 每日对话（2026-09-22）

**碰撞：** 用户 9/21 让 Agent 研究 Jev 模型（TypeSafe AI 9/15 发布的首个 System One 模型，用 Choice / Score / Noul 把自然语言转成类型化、已校准的判断与概率，官方口径「不会幻觉、70–500ms」，专做分类／评分／路由），会话中断但素材完整。拿第三方实测（jev-arena，1 万条评论，Jev 1.13 vs DeepSeek Flash）冲撞本概念的「场景匹配」公理：Jev 快 4 倍（203.2s vs 823.5s）、便宜 44%（$0.84 vs $1.50），但三项准确率**全输**（相关性 94.70% vs 96.26%、情感 82.91% vs 84.54%、意图 77.90% vs 80.33%）。专用模型在自己最擅长的分类任务上没赢通用模型 → 「场景匹配」匹配的到底是准确率，还是吞吐？模型路由的第五个变量候选：**吞吐经济性**（单位时间处理量 vs 单位准确率）。

**纵深：** 1614 年纳皮尔对数表 → 20 世纪电子计算器。对数表的长处是快，而且「不会算错」——因为能回答的范围事先印死在纸上，没有自由发挥的余地；Jev 的「不会幻觉」同理：不是模型更聪明了，是它被允许输出的选项本来就只有那么几种。表最终被计算器吃掉，不是因为表不准，而是算力变便宜、通用工具犯错的代价降到了可接受线以下。**决定表能活多久的从来不是表有多准，是通用工具犯错有多贵**——幻觉在客户场景里仍然昂贵，所以「表」还有活路。（避重复：不复用本概念已用的 Sloan 阶梯、集装箱／海关、急诊分诊台、西南航空。）

**落地：** 客户问「AI 用哪个模型才准」，「看场景」等于没答；把问题翻成「你缺的是准度，还是吞吐」。消费电子客户的评论打标／工单分类／线索评分都是万条量级的活，Jev 那组数字（快 4 倍、便宜 44%、准确率低 2 个点）正是这类客户该算的账：下游还有人复核 → 用准确率换速度划算；结果直接进决策链 → 反过来选。行动：挑一个客户已经在跑的打标场景，把「单条成本」和「单条准确率」拆成两栏算一遍，替掉增购话术里的「我们模型最强」。
