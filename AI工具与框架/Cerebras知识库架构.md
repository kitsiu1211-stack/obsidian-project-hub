# Cerebras 知识库架构

> 来源：Cerebras 内部实战总结

## 核心原则
**让数据留在它产生的地方。** 不要幻想把所有内容迁到一个统一平台——信息总是在最方便的地方产生（Slack 讨论串、代码仓库 PR、Jira 状态）。知识库的任务是去数据存在的地方找人，而不是反过来。

## 混合检索（四层互补）

| 技术 | 解决什么问题 | 飞书对应 |
|------|------------|---------|
| **全文搜索** | 精确 token 匹配（报错字符串、flag 名、host 名） | 飞书搜索 |
| **Embedding** | 语义相似（"restore hangs" ↔ "checkpoint stalls"） | 豆包/Aily 内置 |
| **IDF（逆文档频率）** | 区分信号和噪音（"sounds good thanks" 得分归零） | SkillHub 需要 |
| **时间衰减** | 结果会过期（6 个月前的 infra 讨论可能已经无效） | SkillHub 需要 |

## 与现有体系的关系

- **全文搜索** → 飞书原生搜索已覆盖
- **Embedding** → 豆包/Aily 已有语义检索能力
- **IDF** → 当前 SkillHub / 知识库 **缺失**，是下一步重点
- **时间衰减** → 同样缺失，知识如果不衰减就会被旧信息污染

## 启示

Cerebras 的架构本质上是在说：知识库不是"建一个地方存东西"，而是"建一层检索逻辑，去信息产生的地方抓"。这对我们 SkillHub 的检索层设计有直接参照意义。
