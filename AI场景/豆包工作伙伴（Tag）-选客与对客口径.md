## 一句话

新版豆包工作伙伴（Tag）**不是问答机器人、也不是个人 AI 助理，而是能进群「当同事」的团队级智能体**。
对标 Anthropic 2026-06-23 发布的 **Claude Tag**（官方定义：把 @Claude 当团队成员拉进 Slack）。

## 类比框架：把它当新入职同事（客户沟通用这个讲）

| 对人的动作 | 对 Tag 的动作 |
|---|---|
| 把人拉进部门群/项目群 | 把 Tag 加进群聊 → 自动继承群内文档权限 |
| 给他业务系统/代码仓库权限 | 接业务系统 → 才有企业上下文 |
| 新员工权限独立，不继承 leader 的 | 同样独立：给什么才有什么 |

**超越人类的地方**：7×24、无限带宽、越用越懂组织上下文；是**组织资产**（不随个人入离职流失），不是个人资产。

## 选客尺子（一）：什么样的工作流适合

1. **流程真正在飞书一方生态闭环**（豆包 / Migo / 多维表格 Base）——飞书只当聊天工具、工作流在外部的客户不适合
2. **硬核重复工作流**：需求进线→评审→PRD→研发上线；售后工单接单→派单→闭环
3. **有容错空间**：
   - ❌ 不做：薪酬核算、财务对接等不允许出错的环节
   - ✅ 适合：信息汇总、工单分发（下游有人 review）

现成演示场景：售后工单闭环 / 产品需求评审 / 周报（可跨群发）/ Bug 修复分析 / 设计支持 / 数据分析

## 选客尺子（二）：对接人与公司画像

**对接人（最关键）**
- 不一定 CEO；但要**懂 AI/Agent 的先锋**（已在用 CLI + Codex/Claude 办公）
- 是**团队 leader、有决策权**
- 了解本部门具体场景，第一次沟通就能**脱口而出具体 case**
- CEO 的作用 = **立 flag 给导向**，具体由 1~N 个 **AI builder** 维护找场景

**公司**
- ✅ 已规模化用 Codex/Claude；信息相对透明（Tag 跨群带上下文，部门墙极强不适合）；主要业务在飞书闭环；正在推 AI 转型
- ❌ 不合适：高敏感数据场景、信息强隔离、要求 100% 准确

## 成功标准

**两周内让 Tag 拿到「铁饭碗」**——占住某一条（几条）工作流，产生粘性，客户后面才愿意付费。
用不起来 = 打杂员工，会被「试用期淘汰」。

## 申请与落地流程（两轮筛选）

1. CSM 初筛（按上面两把尺子）
2. 填报名表 —— **最关键一栏「想用 Tag 落地的场景」，必须写透**（只写「研发场景的工作流」这种会被直接拒）
3. 产研二筛（只看场景，不看关系）
4. 约 1v1 聊场景是否真落地
5. 拉群开通（客户对接人 + CSM + 产研）→ 客户自己建 Tag、起名、拉进团队找场景
6. **前两周不驻场**，观察客户能否自发起用；高潜客户产研出人陪跑

## 收费 / 时间口径

- **前 2-3 周 token 全免**；后续付费方案未定，但**一定还会收费**
- 后台「积分消耗」只是预览，**不与现有 AI 积分包/加油包挂钩，不产生真实费用**
- 愿签《体验改进计划》→ **优先开通** + 后续**近 1-2 折**优惠（法务盖章，对接人：王芷伊）
- 对客口径：**尚未正式发布、只支持定向邀请、属于「期货」**，不承诺开通时间
- 材料给法：一般咨询 → 只给 landing page / 官方对客材料；确定聊场景落地 → 再给详细文档

## 答疑精华（客户会问）

- **不替代 Aily**：线上原「团队智能体」继续运行；最终 Tag = 豆包工作里的「伙伴」功能模块，不会同时存在
- **一个团队一个就够**：几十~上百人闭环组织，一个 Tag 分各种场景群；一人开一堆 = 纯烧钱
- **权限同人**：进哪个群、开哪个文档，它才知道什么
- **谁指挥都差不多**：它是独立个体
- **会在你不在的群里主动说话**（数字员工自运行，不逐条问你）
- **不追求秒回**：定位长程工作（给一件事，两天两夜后回来），仍远快于同类人类
- **不用于模型训练**；Tag 资产**归属整个租户**
- **用成个人 agent 会被关停**：已开通客户会被访谈，发现当个人助手用直接关
