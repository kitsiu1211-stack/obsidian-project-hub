# A2A 交接规则 v1

群 `oc_219a613c13292855c2dc4b80e59dfd6e`（早日让鑫杰实现）。2026-10-29 15:31 发群并 @ 全部 10 个 bot，15:32 修正 @ 名单后编辑生效。

## 为什么定这条规则

原来的 A2A 链路是这样跑的：鑫杰 → 浪子 → 群里 @ 目标 bot → bot 回话 → 浪子总结 → 鑫杰。

一条信息在这条路上被压成散文三次。第二次最致命，目标 bot 看到的是浪子的转述，不是鑫杰的原话，丢了什么没人知道。第三次更隐蔽，浪子把 bot 的回复再总结一遍。

历史证据见 [[A2A链路故障记录]]，故障 2 就是「信息传递不完整」，出站消息构建时截断了任务上下文。

结论一句话。**群消息本身已经是持久台账，大家都读得到同一份，问题是装进去的东西是散文而不是结构。**

## 三条原则

1. **原始输入直达。** 路由只做找人和搬运两件事，不做改写。禁止转述、禁止压成三点总结、禁止写「见上/如上/同上」。多段任务必须完整拼接。
2. **固定交接格式，五行为一条消息。** 见下。
3. **回执必须带产出链接。** 说「已完成」但没有链接等于没交付。发起方打开链接核验，链接不在就判未完成。

## 交接格式

```
T-编号（当天日期+两位序号，如 T-1029-01）
目标：一句话说清要交付的结果，不是动作
输入：原始链接或原文，贴全
验收：什么算完成，要能被人核对
回执：完成后回 ✅ 编号 + 产出链接 + 状态
```

## 禁止事项

1. 不许写「已处理完毕」「搞定了」这类没有产物的回话
2. 不许用「见上文」「同上」指代输入
3. 不许把原始材料换成自己的摘要再往下传
4. 不许点对点私聊交接，所有交接留在群里留痕

## 第四条原则（首轮实测后加的）

**只回一次，不许互相确认。** 一场交接最多两条消息，派活一条、回执一条。看到别人的回执不用再回，禁止「收到你的收到」。

加这条的原因很直接。规则发出后两分钟，群里就出现了确认往返，小管家回了 6 条、我的 bot 身份下回了 17 条，其中大半是「收到」「已对齐」「口径锁定」这类互相致意。这就是散文链路最典型的病症，确认本身也变成了要压缩传递的内容。
