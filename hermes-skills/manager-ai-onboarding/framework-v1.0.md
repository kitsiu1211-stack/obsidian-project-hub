# 管理者 AI 0→1 转型：从晋升需求到 AI 协同

> 帮助非技术管理者在 1 周内完成：从不碰 AI → 能搭 Agent / 用 Skill / 配 Cron → 与 Agent 日常协同。

---

## Compiled Truth

帮助管理者完成 AI 转型，核心不是教技术，而是**用管理场景作为锚点 + 用晋升需求作为动力**。

五个阶段不可跳过：扩散（摊开所有可能）→ 收敛（锁定 2 个落地场景）→ 脚手架（手册而非教程）→ 上手（1 周出成果）→ 复盘（出数据 + 出故事）。

管理者不需要会写代码。他只需要知道「每天最痛的那个重复劳动是什么」，然后你帮他把 AI 接进去。**你搭基建，他只管说话。**

---

## 五阶段框架

### 阶段 1：扩散 — 摊开所有可能

**目标**：让学员看到 AI 能做多少事，激发「原来可以这样」的认知冲击。

**动作**：
1. 教练与 AI Agent 先扩散：会议旁听、客户 360、知识治理、经营分析、实时语音、Multi-Agent 等方向全部列出
2. 与学员开会：让他了解这些方向，但不做筛选
3. 关键策略：**先宽后窄**——不限制想象力

**检查点**：学员能说出至少 5 种 AI 可以帮他的场景（不要求精准）。

---

### 阶段 2：收敛 — 锚定管理痛点

**目标**：从扩散的 10+ 方向中，筛选出学员「不做就难受」的 2 个场景。

**筛选原则**：
- ❌ 不用「能帮你省多少时间」筛选
- ✅ 用「这件事不做会怎样」筛选
- 场景必须和晋升答辩的叙事线对齐

**动作**：
1. 让学员逐项校准：每个方向回答「这个跟我的日常管理有什么关系？」
2. 筛掉「锦上添花型」方向（如AI写作），保留「雪中送炭型」（如数据获取）
3. 锁定 2 个场景：一个偏工具效率（立即可见），一个偏管理洞察（答辩亮点）

**卓越案例**：
| 场景 | 类型 | 理由 |
|------|------|------|
| 业绩客户数据助手 | 工具效率 | 「每天手工查 C360 太慢」 |
| 内部群信息提炼助手 | 管理洞察 | 「群消息太多，漏掉关键信息」 |

**检查点**：两个场景都是「他已经在做的事」，不是「你觉得他应该做的事」。

---

### 阶段 3：脚手架 — 手册不教程

**目标**：给学员一套「照着做就能跑通」的操作手册，零 AI 理论。

**手册铁律**：

| 规则 | 例子 |
|------|------|
| 只说怎么做，不说为什么 | ✅ 「打开 Aime 对话框，输入 `查 XX 客户`」 |
| | ❌ 「Aime 是一个基于 C360 CLI 封装的对话式 Agent...」 |
| 前置准备标注「已完成」 | ✅ 「CLI 工具（已安装）- 跳过此步」 |
| 每步一句话能操作 | ✅ 「打开飞书，搜索 Aime 智能助手」 |
| 不教理论，不给背景 | 原理/架构/设计思路→全部删除 |
| 用截图 + 箭头，不用段落文字 | 一张截图抵 200 字 |

**交付物模板**：飞书文档，结构如下：
```
1. 前置准备（已完成的标注 ✓）
2. 第一次使用（5 分钟）
3. 日常使用（1 分钟/次）
4. 进阶技巧（可选）
5. 遇到问题怎么办（常见报错翻译成大白话）
```

---

### 阶段 4：上手 — 1 周出成果

**目标**：学员在 1 周内从「要人教」变成「自己能改」。

**节奏**：

| Day | 目标 | 教练做什么 | 学员做什么 |
|-----|------|-----------|-----------|
| 1 | 配置 | 把 CLI/API/Cron 全搭好 | 打开手册，跑通第一条命令 |
| 2 | 验证 | 旁听，不干预 | 独立跑通一个完整流程 |
| 3 | 加量 | 演示「改参数」的乐趣 | 自己改一个 Cron 时间 / 加一个客户 |
| 4-5 | 放养 | 不主动问，等他来找你 | 日常使用，碰到卡点自己先试 |
| 6-7 | 扩展 | 问他「还想加什么」 | 主动提 1 个新需求 |

**关键原则**：
- 第一天必须跑通——哪怕是最简单的「查 1 个客户」
- 第三天必须有正反馈——「改参数」是让他觉得「我也能改」
- 第五天必须有主动行为——他主动提需求 = 转型成功

**常见卡点**：

| 卡点 | 表现 | 解法 |
|------|------|------|
| 「不知道从哪开始」 | 给了手册也不看 | 录一段 3 分钟视频，口头走一遍 |
| 「怕搞坏东西」 | 不敢改参数 | 告诉他「改了不会坏，最坏就是恢复默认」 |
| 「觉得不如自己手动快」 | 没用 2 次就放弃 | 给他看自己的 Before/After 数据 |
| 「问到一半不敢问了」 | 觉得问题太蠢 | 回复风格：「正常，我也遇到过」 |

---

### 阶段 5：复盘 — 出数据 + 出故事

**目标**：把 1 周的使用经验转化为答辩素材。

**数据采集**（从 Day 1 开始记）：

```
场景：业绩客户数据助手
Before：每天打开 C360 → 输入客户名 → 翻页找 → 手动汇总 → 发给老板（15 分钟/次，每天 2-3 次）
After：@Aime "帮我查 XX 客户" → 30 秒出结果（省时 95%）
频次：已使用 XX 次
省时：累计约 XX 小时
```

**故事框架**（用于答辩）：

> 我作为团队管理者，发现每天花 30-45 分钟在做手工数据查询和汇总。这个时间本可以用来辅导下属或思考策略。我搭建了一套 AI 数据助手，把 C360 查询、客户跟进、业绩看板都接入了 Agent。现在团队成员只需要在飞书群里 @Agent 就能拿到客户画像，我从查询者变成了引导者，团队从「等我给数据」变成了「自己拿到数据」。

**检查点**：
- 有 Before/After 对比数据
- 有使用次数/省时统计
- 有「从查询者变引导者」的叙事

## 适用边界

| 条件 | 是否适用 |
|------|------|
| 学员有晋升/绩效压力 | ✅ 最佳场景 |
| 学员纯兴趣驱动 | ⚠️ 动力不足，需要更强的正反馈 |
| 学员有技术背景 | ✅ 可跳过脚手架，直接给 API 文档 |
| 学员完全抵触 AI | ❌ 先解决心态问题，再走框架 |
| 外部客户（非内部晋升） | ✅ 框架通用，场景替换为客户业务 |
