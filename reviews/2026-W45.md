## 零、本周期核心发现（≤3）

1. 🔴 **输出截断是本周最大的隐性浪费：11 次「截断续写」，累计 121 次**。全部来自「每日工作摘要」的质检子会话（质检员打分为长结构化输出，被 `max_tokens=4096` 拦腰截断，然后系统再发一条「从断点继续」重跑）。**每一次截断 = 一次完整重发 = 双倍 token**。今天已把 `model.max_tokens` 4096 → **8192**。

2. 🔴 **「@ 不生效」第 3 次变体：这次不是忘 @，是全角引号**。`<at user_id=“ou_717542…”>` 用的是全角 `“ ”`，飞书不解析、**静默降级成纯文本**（不报错）。历史三次同源事故：忘 @（10-28）→ @ 错人（10-29）→ 全角引号（11-06）。今天把校验做成了**脚本闸** `check_at_tags.py`，不再靠记性。

3. 🟡 **认知对话本周 5 次超时，11-03 整天没出内容**。失败原因全部是 `idle for 754~1073s — waiting for non-streaming API response`，时间点全在早晨 09:0x/09:5x。11-02、11-06 靠补跑哨兵救回；**11-03 双次失败后无人兜底，当天认知对话为零产出**（会话里只有 prompt、没有 assistant 回复）。

### 模式问题（系统性缺陷，≥2 次）

**P1 🔴 @ 标签三连变体 —— 文字规则三次都没挡住**
- 10-28 忘 @ → 10-29 @ 错人 → 11-06 全角引号。
- 前两次修复都是「写进 memory / pitfall」，第三次证明：**同一目标的不同失败形态，靠记规则堵不完**。
- ✅ 本周首次做成**代码闸**：发送前跑 `check_at_tags.py`，rc≠0 不许发（已用三条真实事故文本回归，全拦下）。

**P2 🔴 输出截断 —— 每周 11 次的重复付费**
- 症状：assistant 输出被 `max_tokens` 截断 → 系统注入「从断点继续」→ 模型重读上下文再写一遍。
- 累计 121 次（占全部会话历史的相当比例），触发场景高度集中：**质检员/评估类长结构化输出**。
- ✅ 已把上限提到 8192；配套还没做的是**在质检 prompt 里写死篇幅上限**（「每条结论 ≤ 2 句」），双保险。

**P3 🟡 认知对话早晨超时 —— 环境类，但没有失败告警**
- 本周 10 次执行：5 failed / 4 completed / 1 unknown；失败耗时 754–1073s，全部落在 09:0x–09:5x。
- 与上周判断一致：`waiting for non-streaming API response` ≈ **机器休眠/网络栈唤醒**，不是 provider 故障、不是选错模型——**别去换模型**。
- 真问题不是超时，是**超时之后没人知道你漏了一天**（11-03 就是这样静默丢的）。
