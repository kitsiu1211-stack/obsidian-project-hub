# AI 基础概念入门

> **用途**：面向纯小白学员，在正式分享前做 5-10 分钟铺垫
> **目标**：让学员听懂后续内容中的核心术语，不产生畏难情绪

---

## 一、三个层次：人 → 工具 → 助手 → 同事

大多数人对 AI 的理解停留在第一层：

| 层次 | 例子 | 你能做什么 |
|------|------|-----------|
| 1. 工具 | 豆包、DeepSeek、ChatGPT 聊天框 | 你问它答，一问一答 |
| 2. 助手 | 企业版豆包 + 知识库 | 它能读你的文档，回答更准 |
| 3. 同事 | Agent（智能体） | 它有记忆、能定时干活、能操作电脑、能跟其他 Agent 协作 |

**你正在用的豆包，是第 1 层。我今天展示的，是第 3 层。**

---

## 二、核心概念（用大白话）

### 大模型（LLM）
> 就是 AI 的"大脑"。豆包背后是一个大脑，DeepSeek 背后是另一个大脑。不同的大脑擅长不同的事——有的擅长写代码，有的擅长做图，有的擅长中文表达。

- 豆包 = 火山引擎的大脑
- DeepSeek = 性价比之王，理工直男风格
- Kimi = 超长上下文
- Minimax = 最早做桌面 Agent 的

### Agent（智能体）
> Agent = 大模型 + 记忆 + 工具 + 定时任务。

**聊天机器人 vs Agent 的区别**：你问豆包"今天天气怎么样"，它回答完就忘了。Agent 会记住你是谁、你做什么行业、你的偏好，还能每天早上 8 点自动帮你查天气发给你。

简单理解：**豆包是你电话那头的人，Agent 是你办公室的同事。**

### Skill（技能）
> Skill = SOP（标准操作流程），告诉 Agent 一件事情怎么做。

例如：你给 Agent 一个 Skill 叫"客户动态预警"——
1. 每 2 小时去网上搜一遍我客户的名字
2. 找到相关新闻
3. 总结成 3 句话
4. 用我的语气写一段话术发给我

**Skill 就是 Agent 的"工作手册"。**

### Token（词元）
> Token = AI 的"电量"。你每问一个问题、每让它做一件事，都消耗 Token。

就像手机话费：发一条消息扣一点，打个电话扣更多。

- 简单问题 = 几百个 Token
- 让 Agent 干一件复杂的事 = 几万个甚至几十万个 Token
- DeepSeek 大概 100 万 Token = 1 块钱

**我一周花了 100 块钱 Token，因为一直在测试 Agent 入会。**

### Context（上下文）
> Context = Agent 对你的了解程度。

你刚认识一个人，他只知道你的名字。共事半年后，他知道你的工作习惯、你喜欢的表达方式、你的客户是谁。这就是上下文。

**飞书最大的优势就是上下文**——你的聊天记录、文档、会议、审批都在飞书里，Agent 接入飞书后天然就"了解你"。

### Engineering（工程）
> Engineering = 让 Agent 更稳定、更高效的系统设计。

就像盖房子：
- 大模型 = 建材（砖头、水泥）
- Engineering = 建筑设计（怎么搭才不倒、怎么让空间更好用）

你不需要懂，但要知道有人在帮你做这件事。

### Harness Engineering（驾驭层工程）
> 最新概念，北京刚写进政策文件。意思是：不让 Agent "裸奔"，给它装好安全带、方向盘、刹车——让它可控制、可追溯、可管理。

## 三、一句话区分

| 概念 | 一句话 |
|------|--------|
| 大模型 | AI 的大脑 |
| Agent | 有记忆、能干活的 AI 同事 |
| Skill | Agent 的 SOP 工作手册 |
| Token | AI 的电量/话费 |
| Context | Agent 对你的了解程度 |
| Engineering | 让 Agent 更稳的系统设计 |

---

## 四、一个类比帮助记忆

把 Agent 想象成你招的一个实习生：

- **大模型** = 他的智商和专业能力
- **上下文** = 你教了他多久、他了解你多少
- **Skill** = 你给他的工作流程手册
- **Token** = 他的工资（干活就要花钱）
- **Engineering** = 公司的管理制度（让他不出错、效率高）

你不需要会写代码，就像你不需要知道实习生的大脑怎么运作——你只需要知道怎么给他布置任务、怎么检查结果。
