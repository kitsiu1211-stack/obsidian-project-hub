## 分享的四大场景（逐条还原）

### ① 客户动态监控 Agent（最受欢迎案例，67% 学员最感兴趣）

**痛点**：手上 30 家客户，过往只知道飞书产品更新，很少了解客户投融资/产品/人事动态。老板觉得「你只有要钱才找我」。

**演进**：
- V1：每天早 8 点 cron 定时推送全网客户动态 → 信息过载，AI 噪音
- V2：升级 heartbeat 心跳机制，每 2 小时查一次，只有 1-2 条关键动态 → 聚焦、时效性强（CEO 都不知道的 PR 稿我先知道）

**架构**：Generator + Evaluator 双角色（不让 agent 既当运动员又当裁判）→ 调了十几轮，五重认证机制（多平台发布时间提取、过滤「近日/近期」模糊时间）

**成果**：客户觉得「你比我还先知道我们公司动态」，信任关系大幅提升，从动态里挖出商机（如拓竹 → 邀约豆包大模型合作）

### ② 妙搭商务计算器（人生第一个 vibe coding 工具）

**痛点**：升级报价 8 步流程 4-5 分钟，还要手写计算逻辑发给客户。

**方案**：妙搭搭计算器，粘贴一段文字自动识别字段（类似快递地址识别），一键生成报价 + 计算逻辑明细，**5 分钟 → 20 秒**。

**关键认知**：「业务 + AI」是加法，让 AI 重构整个工作流才是乘法。搭起来只要半天，用真实场景去调。

### ③ 个人知识图谱（Obsidian + Agent + 艾宾浩斯）

- 公众号文章 → Agent 分析 → 结构化写入 Obsidian
- 知识自动关联（主题二 ↔ 主题八），形成个人知识图谱
- 艾宾浩斯遗忘曲线 skill：每天推送认知对话（碰撞/纵深/落地/等你）
- **核心观点**：AI 对个人最大价值不是提效，是**提升认知**——认知决定一个人上限

### ④ Agent 集群协作（11 人最喜欢的环节）

- 群里只有 1 个真人 + 12 个 Agent（WorkBuddy / Kimi Code / 安全合规 / 服务 / 迁移…）
- 主 Agent（Hermes）负责调教新 Agent、分发任务
- 案例：客户问「外包怎么加入飞书」→ 主 Agent 读 4 篇文档 → 筛 1-2 篇最合适的 → 直接转发
- RunCat 项目：主 Agent 判断价值 → 找 Kimi Code 重构，非技术背景全程不写代码
- **Agent to Agent 是未来大方向**：单 Agent 用久了上下文膨胀会幻觉，要分场景 + 主 Agent 协调
